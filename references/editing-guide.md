## 场景改写例证

以下两例取自固定上游版本的合成样本，保留输入与推荐输出，去掉主观评分。它们不是实测产品数据。

### RS-07：只改 docstring

输入已经包含函数实现，因此可以据此说明行为，不必补性能或复杂度。

```python
def deduplicate(items: list[str]) -> list[str]:
    """
    通过采用先进的去重算法，全面优化数据处理流程，显著提升整体性能，
    为用户提供更加高效、可靠的使用体验。该方法充分体现了对代码质量
    和工程卓越的不懈追求。
    """
    return list(dict.fromkeys(items))
```

改写：

```python
def deduplicate(items: list[str]) -> list[str]:
    """按首次出现顺序去重。"""
    return list(dict.fromkeys(items))
```

### RS-14：保留欢迎交流的态度

输入：

> 稳稳地接住所有人
>
> 真诚、友善、团结、专业。无论你是来提问、提意见，还是单纯想说句话，这里都会稳稳地接住你。

改写：

> 提问和意见都欢迎
>
> 真诚、友善、团结、专业。来提问、提意见，或者说句话，都可以。

从其余样本提炼的编辑提醒：具体功能、数字、负责人、复现结果和排期必须来自输入；材料不足就指出缺口。口语化不等于摘要，不能擅自省略条件或观察过程。心理和能力判断没有依据时，不用另一种确定评价替换。标点可以局部调整，但引文原句、作者态度、统计量和适用边界仍须保留。以上分别参考 RS-06/08、RS-11、RS-13、RS-19/20；它们的整份推荐稿没有作为正例采用。

## 合理对比与修改范围

上游 SF-40 是一篇反对过度整理的三段合成文章：作者以多组对比区分整理与表达，并用一篇文章从 1800 字缩到 1000 字的假设讨论节奏丢失。这里的对比承担全文论点，可以保持原样；它不是看到任何对比都必须保留的通用豁免，也不能凭句型数量要求删掉有意义的否定或反例。

先辨认每个对比表达的是排除、程度、条件还是修辞。改写后应保持同一种关系。用户要求句内修改时，保留句子与段落顺序；只有得到结构调整授权才能删并重排。原文已经准确自然时可以不改，不为了展示工作量强造改动。

保真错误与风格偏好分开判断。句长是否交替、定位句是否够鲜明，可以有多个合理答案；新增能力、改变责任、漏掉限定条件则是语义错误。回读先核对输入信息是否仍在，再核对输出每个陈述能否回指输入。上游发布门槛、字数比例和模型通过率不作为这份编辑参考的通用要求。
