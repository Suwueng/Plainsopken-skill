### A2 · P2 · 参考仍给出违反入口边界的动作

位置：[structures.md §14](../../skills/plainspoken/references/structures.md#14-分条列点强迫症)、[中文表的无源引用](../../skills/plainspoken/references/phrases-zh.md#无源引用公开写作中尤其像-ai)、[operation-manual.md §15](../../skills/plainspoken/references/operation-manual.md#15-量化表述有歧义)。

最明确的冲突是 §14：把三个编号步骤列为反例，把合成一句正文列为正例。入口的 [Core stance](../../skills/plainspoken/SKILL.md#core-stance) 和三档 scope 明确要求保留列表形式，连用户授权的格式转换也另属编辑任务。因此这个正例已经不适用于当前职责。

另两处需要收紧：中文表仍给「数据显示」提供「直接给数据」的动作，可能绕开入口对整条无源论断的处理；微操作手册允许在 chat/public-writing 删除被判断为不关键的歧义量化短语，与入口默认保留关系并标待确认的路线不同。顶部「以 SKILL.md 为准」能确定冲突时的优先级，但不能让这些具体动作成为一致的正例。

建议先把编号步骤的推荐稿改为保留列表，来源及量化条目引用入口的对应合同，不另维护一套替代动作。验收应使用普通短列表、无源数字论断与歧义倍数的合成输入；不能只复测 release-note 列表，也不能只检查链接存在。本轮确认了静态不一致，尚未执行这组三道新行为用例，不把它们计作模型失败。

### A3 · P2 · report 忽略已声明的逐例执行记录

位置：[harness.py 的执行信息判断](../../scripts/harness.py)。核心检查只读取运行级 `model/settings/executor/skill_path/references_read`，未校验 `per_case_execution` 引用的记录。

隔离复现保留了满足原判据的输出与匹配评审，运行级信息指向正确快照，逐例记录却指向另一技能、标记 `completion_status: failed`，报告仍返回 `pass`。再删除这份已声明的逐例记录，报告仍返回 `pass`。这是校验器的合成输入，不能当作新模型通过结果。

影响是报告无法拦住可直接检查的执行记录缺失或矛盾；混用输出、失败重试或记录遗漏时仍可能放行。此问题不等于已有全量运行记录有错：本轮另行核对它声明的全部 60 份逐例／逐轮记录，文件均存在、路径均正确且均标为完成。

建议在声明了逐例记录时，检查记录存在、读取路径、完成状态及与运行级信息的一致性；旧版仅有运行级记录的兼容边界另行说明。验收是上述缺失或矛盾记录不能得到 `pass`，已有完整运行仍能通过。不需要增加模型 API 客户端。

### A4 · P2 · 安装备份路径未纳入不重叠检查

位置：[manage.py 安装与备份](../../scripts/manage.py)。工具检查源与目标不重叠后，另算 `destination.parent.parent / "skill-backups" / destination.name`，没有检查该路径与源、目标的关系。

两种隔离复现成立：

- 目标形如 `<隔离目录>/skill-backups/plainspoken` 时，备份根目录等于目标本身，工具尝试把目录移动到自身子目录，报 `Errno 22 / Invalid argument`。复制当前脚本的 CLI rollback 也复现了同一错误，且通过了开发仓库保护检查。原目标内容保留。
- 备份根目录等于安装源时，更新成功但把旧目标的 17 个文件备份到源目录内部，源目录因此产生额外内容。

默认安装路径未在本轮发现这类失败；问题发生在工具支持的自定义目录安排中。建议在任何 mkdir、暂存或移动前校验备份根目录与源、目标及开发仓库的关系，选择不重叠位置或明确拒绝。验收同时覆盖重叠拒绝、源目录保持原样、常规更新与失败恢复。
