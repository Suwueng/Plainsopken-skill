# 开发与验证

## 范围与依据

这里的 harness 是支持技能开发的本地环境：约定、用例、快照、实际输出、评审和隐私检查。运行技能不依赖这个工程。

技能源码位于 `skills/plainspoken/`；开发文档、脚本、测试和用例保留在仓库根的相应目录，与技能共同版本化。根 `LICENSE` 是唯一人工维护来源，通过 `python3 scripts/manage.py sync-license` 显式同步技能内的完整普通文件副本，两份均纳入版本控制。检查、评测准备和安装要求两份字节一致，不静默覆盖。完整技能包包含 `SKILL.md`、`agents/`、`references/`、`LICENSE` 和 `THIRD_PARTY_NOTICES.md`，不包含开发目录。技能内的相对引用以技能包为边界，不依赖仓库中的开发文件。

短入口、按需文档和可执行约束参考 [OpenAI harness engineering](https://openai.com/index/harness-engineering/)；任务相关判据、执行与评审分离参考 [Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)。本机参考工程贡献了单份任务计划、本地记录隔离和初始化只验证的结构经验；没有复制其业务代码、数据或机器配置。

## 一次改动

1. 记录合成或脱敏输入、观察到的问题、允许修改的范围和验收条件。小改动使用用例与提交说明；多步骤任务在 `docs/plans/` 维护一份计划，包含目标、验收、进度、决定、验证与未完成事项。
2. 改规则前保存一次 `prepare` 快照，执行相关用例并保留失败输出。冲突影响改法时先明确维护者意图，其余独立工作继续。
3. 只改已证实问题涉及的规则或工具。工具先写异常输入测试；规则先写语义判据，不把当前实现的文本当成真值。
4. 聚焦检查后跑 `harness.py check`；规则修改还需执行相关行为用例，用相同模型、设置、输入和上下文安排比较前后结果。
5. 提交前核对公开差异与暂存区隐私。推送、历史重写、全局安装各自需要维护者当前授权；验证不隐含这些动作的授权。

计划是唯一任务状态源，不再维护平行的 feature list 或进度数据库。完成后在同一计划标记完成并记录证据。带私人内容的计划与临时探索放 `work/`，只把脱敏后的结论写入公开计划。

## 检查分层

| 命令 | 证明什么 | 不证明什么 |
|---|---|---|
| `python3 scripts/manage.py check` | 运行文件、基础元数据、本地链接目标存在、许可副本一致 | 完整 YAML、锚点、加载发现、语义质量 |
| `python3 -m unittest discover -s tests -v` | 工具正常与异常路径；安装使用临时目录 | 真实全局安装成功、模型能力 |
| `python3 scripts/harness.py check` | 上述检查、用例结构、work 忽略规则、候选树隐私 | 历史无隐私、实际行为通过 |
| `python3 scripts/privacy.py --history` | 本地 refs 可达文件及身份、消息未命中规则 | 全部隐私、远端及悬空对象、分发许可 |
| `python3 scripts/harness.py report --run …` | 指定快照的输出、执行记录、判据与证据完整且通过 | 自动触发、统计显著性、人工判断绝对正确 |

格式检查不代替行为评测。宿主发现需单独记录实际读取路径与结果；不能沿用旧技能名的历史发现记录。

## 评测文件合同

在项目根目录执行，可用多个 `--case ID` 聚焦用例：

```sh
python3 scripts/harness.py prepare --run work/runs/change-before --case purpose-and-state --case entity-relation
```

每次使用新目录。生成内容如下：

- `skill/`：本仓库 `skills/plainspoken/` 的完整运行快照，包含该目录内的 `LICENSE` 和 `THIRD_PARTY_NOTICES.md`，入口为 `skill/SKILL.md`；不读取全局安装副本。
- `manifest.json`：源 commit、dirty 标记、运行文件和用例及请求哈希、本地路径。`source_path` 指仓库根，`source_skill_path` 指当前技能源码入口，`skill_path` 指本次执行的快照入口；旧记录可以没有 `source_skill_path`。未提交状态可实验，但不能声称是该 commit 的原样输出。
- `prompts/`：只含技能路径、请求与输入。把单例请求交给执行者，不提供整个用例文件、审计结论或评审模板。
- `outputs/<id>.txt`：完整原始答案。不得为过测手工润色；重新执行应新建 run。
- `execution.json`：实际执行信息，见下文。
- `reviews/<id>.json`：评审者、输出哈希，以及每条条件的 `pass` 布尔值和具体 `evidence`。
- `report.json`：校验后生成的本地结果，不提交到 Git。

执行后填写 `execution.json`：`model` 写实际模型标识；`settings` 写推理强度、采样设置和上下文隔离情况；`executor` 写宿主或调用方式；`skill_path` 写实际读取的快照入口绝对路径；`references_read` 列实际阅读的快照相对路径。未暴露的模型或设置明确标为未知，不能推测精确 ID。更换模型或设置应另建 run。

工程不包含模型 API 客户端，不读取凭据、不自动计费。可以使用当前助手的独立子代理或人工会话执行。严格比较时每例使用新会话；同一会话批量执行仅作为冒烟检查，记录上下文影响。没有独立会话时如实报告限制。

评审者读取 `cases.json` 和完整输出，先核对语义与范围，再判断风格。对输出文件运行 `shasum -a 256`，将结果填入 `output_sha256`；`reviewer` 标记人工或评审模型。每项 `evidence` 引用输出短片段并解释判据，不能只填“通过”。缺条件、证据或匹配哈希都会保持待评审；字面检查失败不能被人工 `pass` 覆盖。

```sh
python3 scripts/harness.py report --run work/runs/change-before
```

状态为 `not_run`、`pending_execution`、`pending_review`、`fail` 或 `pass`，只有 `pass` 返回 0。汇总先显示失败，再显示未执行或待确认；逐例情况见 `report.json`。报告验证记录一致性，不能独立证明执行者如实声明了模型与读取路径；保留宿主轨迹作为本地补充证据。

## 隐私边界

真实输入、私有项目名、账号、联系方式、机器路径、原始轨迹放 `work/`。禁止用 `git add -f` 绕过；忽略规则无法保护已跟踪文件。

隐私工具分开扫描工作树、暂存区、所有本地 refs 可达历史。包括已删除文件、提交和标签的身份与消息；不检查 reflog、悬空对象或未获取的远端历史。报错只给位置和规则，不复述私人字符串。未识别身份默认报出待审查；维护者已明确批准 Peng Cheng <chengpengsmc@qq.com>，Git 元数据只精确允许该姓名邮箱组合，其他姓名邮箱不能借用这一例外。

通用规则只覆盖路径、邮箱、常见密钥等特征。`work/private-patterns.txt` 可逐行添加姓名、用户名、内部项目名等精确字符串，不支持注释或正则。工具会确认名单被忽略且未跟踪。缺少名单时 `coverage` 为 `generic_only`；有名单也须人工检查组合识别风险。

本地禁传字符串若完全落在已批准公开身份的匹配范围内，可按明确授权豁免；同一字符串出现在个人路径、另一邮箱或其他位置时仍会命中。公开邮箱例外不扩展为整个邮箱域白名单。

当前技能包不附第三方天文词库数据或原始说明，只提供官方查询与获取链接；可按独立条款使用用户已有本机资料，私人位置只放 `work/`。历史扫描中的词库精确路径和哈希例外保留用于核查旧备份，不构成重新打包或公开分发授权。隐私扫描也不判断分发许可。

`.githooks/pre-commit` 检查暂存区，`.githooks/pre-push` 检查历史。审阅脚本后可执行 `git config --local core.hooksPath .githooks`。CI 发生在上传以后，不能充当首次隐私防线。

## 发布与安装交接

首次发布先交付本地差异、检查结果、行为记录和隐私命中。历史有命中就停在审查阶段，不创建远程仓库或推送。此次维护者已确认公开身份并要求优先清理历史，采用仓库外私有备份后精确清理的方式，保留三个提交的内容演进，见[清理记录](plans/privacy-cleanup.md)。以后重写历史仍须当前授权；本次本地清理不授权推送或全局安装。

发布候选提交必须干净，运行内容哈希与受审行为记录一致；改了规则后，旧快照的通过不能代表新内容。最终再次检查暂存区、历史、文件列表和第三方许可。三个旧提交及辅助引用、索引中的词库原件已完成[本地历史清理](plans/dictionary-history-cleanup.md)；仓库外私有备份和被忽略的旧评测快照仍含原件，不得作为公开附件。历史清理不替代后续候选内容审查。记录获准的仓库、commit 与动作，再分别推送或安装。

全局更新沿用 `manage.py` 的白名单、版本清单、扫描目录外备份与回滚。首次旧名迁移由维护者明确执行；演练必须指定临时 `--dest`，工程检查不调用真实安装。
